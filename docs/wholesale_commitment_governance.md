# Revolving and leveraged contractual histories

`examples/wholesale_commitment_governance.py:run(data=None, verify_reference=True, artifact_paths=None, return_audit_artifacts=False)` executes four revolving commitment and three leveraged loan variants. The native R example exposes `run_wholesale_commitment_governance` with the same arguments and optional `engine_path` for the shared packaged governance engine. `artifact_paths` maps resource names to user-selected frozen model files. The default result contains seven summaries; `return_audit_artifacts` additionally returns complete local registries, requests and results.

The frozen models are fitted on the existing public synthetic component training data: weighted binary GLM and group-specific hierarchical calibration for revolving commitments; expert-feature scorecard and holdout logistic calibration for leveraged loans. Independent count-based probabilities are checked before freezing. The 30-day revolving target is not relabelled a two-year target. Leveraged principal matures on 1 January 2026; positive operating cash flow and an earlier covenant warning do not remove the unfunded balloon. Its observed default occurs at that maturity, followed by ten days past due. The revolving branch observes a funded default on 31 January 2024. A cancellable right has not been executed in that branch; the separately demonstrated executed-cancellation scenario is not an observed default or a replacement PD.

Every example input and outcome is synthetic and explicit in `wholesale_commitment_governance.json`. Observed events are separately declared servicing records, not simulated paths reused as validation labels. Decision gates use available operating cash and contractual service. Calibrated standalone PD precedes sponsor support. Origination, knowledge, processing, review, finalization, default, closure and replay dates are independently stored. The shared engine rejects inverted occurrence/knowledge dates and computes days past due from payment dates.

A duplicate review applies once. Finalization and legal closure change assessment lifecycle state without rewriting the original forecast. Historical requests replay exactly after a genuinely fitted later model is registered; a modified event seal fails replay. Python and native R reproduce the complete seven-case audit, including every input, model, recipe and result seal. This example covers governance and event history; workout estimation, cohort performance and portfolio acceptance require their separate components.

Quick tests execute one revolving and one leveraged history; `CREDITRATINGSYSTEM_EXTENDED_TESTS=true` executes all seven.
