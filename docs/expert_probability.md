# Expert probabilities and finite risk networks

These functions calculate with documented expert inputs. They do not authenticate judgments, infer missing facts, or establish empirical predictive performance. All return `CalcResult`; use `.value` in Python and `$value` in R. Python imports are in `creditratingsystem.expert`.

## Elicited prior and observed evidence

`fit_elicited_beta_prior(elicitation, elicitation_contract=...)` requires a contract with `population_id`, `reference`, `known_at` (ISO date), distinct `expert_ids`, distinct `evidence_ids`, and `target`. The target contains exactly `event='default'`, a positive `horizon`, `time_unit` (`days`, `months`, `years`), `probability_measure` (`PHYSICAL`, `RISK_NEUTRAL`), and `conditioning`. Prediction context must agree with this target.

Two elicitation modes are available:

* `{'method':'moments','mean':m,'concentration':s}` gives alpha=m*s and beta=(1-m)*s. Alternatively provide `variance=v`, with 0<v<m(1-m), instead of concentration; s=m(1-m)/v-1.
* `{'method':'quantiles','quantiles':[...],'probabilities':[...],'weights':[...]}` fits weighted squared CDF residuals at at least two strictly increasing interior points. Every weight is positive. The solver searches log shapes in [-18,18] from three declared starts (1,1), (2,18), (18,2). Python uses SciPy bounded least squares; R uses native `nlminb`. A successful fit requires the declared maximum CDF residual (default .01), an interior solution, and a locally identified two-column Jacobian. Saturated/nonidentified or incompatible judgments raise an error; the original judgments and residuals remain in the artifact.

The returned sealed Beta artifact records elicitation strength, source evidence and availability. Its concentration is not an observed sample count. A numerical Beta fit is separate from the expert elicitation process described by [SHELF](https://shelf.sites.sheffield.ac.uk/).

`update_expert_beta_binomial(prior, defaults, exposures, observation_contract=..., predictive_exposures=0, credible_level=.95)` requires matching population/target, new distinct `evidence_ids`, `known_at` no earlier than the current prior, and explicit `conditional_iid=True`, `outcome_complete=True`. Counts must be integers, 0<=defaults<=exposures<=1,000,000. Correlated or censored aggregate counts are unsupported by this model. The posterior artifact can be passed to a later update; evidence cannot be reused. Only supplied evidence IDs can be checked, so callers must preserve stable IDs across sources.

Beta(alpha,beta) becomes Beta(alpha+d,beta+n-d). Outputs distinguish mean, median and equal-tail credible interval. The predictive count distribution for a declared future integer size (at most 100,000) is Beta-binomial: choose(m,k)*B(alpha'+k,beta'+m-k)/B(alpha',beta'). Prior weight s/(s+n), observed counts, predictive mean and variance remain visible. `Beta(2,18)` plus 3 defaults in 100 gives `Beta(5,115)`, with mean 5/120. Distribution evaluation uses [SciPy/R Beta routines](https://stat.ethz.ch/R-manual/R-devel/library/stats/html/Beta.html); interval meaning follows the declared probabilistic model.

## Opinion pools and likelihood evidence

`pool_expert_probability_distributions(components, weights, support=..., rule=...)` accepts rows of normalized component distributions. A discrete support is `{'kind':'discrete','values':['low','high']}` with probability masses. A histogram support is `{'kind':'histogram','breaks':[0,1,3]}` with constant densities in each bin. Integrals must equal one within 1e-10; the routine does not silently repair invalid distributions. Nonnegative weights are normalized; each zero weight needs `exclusion_reasons={'0':'reason',...}` using zero-based component indices.

`rule='linear'` forms the weighted arithmetic pool. `rule='logarithmic'` forms the weighted geometric density and divides by its exact finite/bin normalization constant. Disjoint positive-weight supports raise an error. Output includes density/mass, bin masses, cumulative probabilities at ordered support points/right bin endpoints, log normalization and component total-variation disagreement from the linear pool. Histogram within-bin CDFs interpolate linearly. Opinion correlation does not multiply evidence; the weighting decision is explicit. See [de Carvalho et al., logarithmic pooling](https://arxiv.org/abs/1502.04206v2).

`update_odds_from_evidence(prior_pd, evidence_groups, dependence_contract=..., previous_evidence_ids=None)` uses one finite strictly positive `joint_likelihood_ratio` per group. Each group contains a unique `group_id`, distinct `evidence_ids`, and a `reference`. Evidence IDs cannot overlap groups or previously applied evidence. With multiple groups, the contract requires `conditional_independence_given_default_and_survival=True` and a reference supporting that assumption. A joint LR must already account for dependence within its group. Computation adds log LRs to prior log odds; .1 with LR2 gives 2/11. Dogmatic prior 0/1 remains unchanged under finite positive LRs; zero/infinite LRs need a richer explicit event model and are rejected here.

## Preference consistency and rating agreement

`check_expert_preference_consistency(comparisons, items=..., incomplete_policy=..., tolerance=1e-8)` takes a positive reciprocal matrix; ratio[i,j] means importance of i divided by importance of j. Diagonals equal one within declared log tolerance. Missing pairs are null/NaN in Python and NULL/NA in R, with both reciprocal cells missing. `incomplete_policy='error'` rejects gaps; `'connected_components'` returns separately normalized priorities for each connected component, with no invented global scale.

For every observed pair, log least squares minimizes (theta_i-theta_j-log ratio_ij)^2 with sum(theta)=0, then normalizes exp(theta). Outputs expose pair residuals and every observed triangle residual log(a_ij)+log(a_jk)-log(a_ik). An iterative DFS returns witnesses for back edges in the strict-preference graph; it does not enumerate every possible cycle. The input matrix is preserved, no automatic repair occurs, and disagreement is not a statistical confidence interval. This is the logarithmic least-squares approach of [Crawford and Williams](https://www.sciencedirect.com/science/article/pii/0022249685900021).

`assess_expert_rating_agreement(first_ratings, second_ratings, ordered_grades=..., rater_pair=..., weighting=..., missing_policy=...)` requires two aligned rater vectors and the complete ordered grade set, including unused grades. `weighting` is `unweighted`, `linear` or `quadratic`; similarity weights are 1{equal}, 1-|i-j|/(K-1), or 1-(|i-j|/(K-1))^2. `missing_policy='error'` rejects missing values; `'pairwise_complete'` explicitly reports exclusions. Chance agreement uses independent empirical rater marginals. Kappa=(observed-expected)/(1-expected); an expected agreement within 1e-15 of one is reported as degenerate, not kappa=1.

Optional `bootstrap_indices` are a matrix of zero-based resamples of the paired-complete cases, each retaining the original complete-case size. Percentile intervals use `confidence_level=.95`, require at least two resamples, and assume independent cases unless the caller supplies a documented valid cluster resampling design. Any degenerate bootstrap replicate suppresses the interval with an explicit count/status. High agreement is not proof of credit-risk accuracy. See [Revelle's weighted-kappa documentation](https://personality-project.org/r/psych/help/kappa.html).

## Finite Bayesian networks

`compile_discrete_bayesian_network(nodes, network_contract=..., elimination_order=None, max_factor_cells=1000000)` freezes complete finite CPTs. Each node has `node_id`, ordered distinct `states`, distinct `parents`, `parameter_origin` (`ELICITED`, `ESTIMATED`, `FIXED`), `reference`, `known_at`, and `cpt`. Every CPT row is `{'given':{parent:state,...}, 'probabilities':[p_for_each_child_state]}`. A root has one row with empty `given`. Every parent-state combination appears exactly once, probabilities are nonnegative and sum to one within 1e-12. Supplied estimated CPTs retain their origin but are not fitted by this function.

The network contract contains `network_id`, `version`, `population_id`, `default_node`, `default_state`, `known_at`, `as_of` and the target described above. Nodes must be available by the network knowledge cutoff. Cycles, duplicate states, unknown parents and incomplete CPTs reject. Lexical topological ordering makes equivalent row orders reproducible; parent and state orders remain meaningful. The default elimination order is reverse topological order; an explicit order must contain every node exactly once. It is not claimed to minimize factor size.

`infer_discrete_credit_network(compiled_network, evidence, query_node=None)` defaults to the declared default node, conditions on each observed state and marginalizes all others. It uses genuine log-domain factor multiplication and variable elimination, with each intermediate factor bounded by the frozen `max_factor_cells` (compile-time integer in [1,10,000,000]). A more appropriate elimination order can make an otherwise oversized query feasible. Outputs include posterior state probabilities, default PD when querying the declared default node, evidence probability and log probability, eliminated variables, peak factor cells, target and network hash. Zero-probability evidence raises `EXPERT_IMPOSSIBLE_EVIDENCE`; positive evidence whose probability underflows is distinctly flagged while the finite log probability remains available. Querying an observed node returns its point mass after still checking evidence likelihood.

Factorization encodes conditional-independence assumptions. These are observational computations, not causal interventions; see [Scutari's primary notes on exact network inference](https://www.bnlearn.com/about/teaching/eng-apm-inference.pdf). Default tests include independent full-state enumeration, closed-form Beta CDF/count oracles, hand pooling/kappa, cycles, impossible evidence and likelihood underflow; no simulation-heavy test is required for this slice.
