# Mature-outcome monitoring and quantitative diagnostics

The six methods return local `CalcResult` objects. They neither assign model roles nor change a model. Python exposes them from `creditratingsystem.monitoring`; native R uses the same function names and parameter meanings. Tables are arrays/lists of named records, not data frames. Dates are ISO calendar dates. All probabilities are physical default probabilities. The caller supplies the resampling paths, making numerical comparisons reproducible across languages.

## Cohort construction

`build_monitoring_cohorts(predictions, outcome_events, coverage, target_contract=..., evaluation_cutoff=...)` creates a content-hashed bundle. Its target contract requires `event="default"`, `probability_measure="PHYSICAL"`, `default_definition`, `unit`, and integer `horizon_days`; optional `default_grade` identifies the absorbing migration grade. `entity_id` denotes the declared observation unit, so a facility target requires facility identifiers. The builder supports default outcomes; realized LGD and incomplete workouts are not accepted as binary default labels.

Every prediction has `forecast_id`, `case_id`, `entity_id`, `cluster_id`, `cohort`, `segment`, `model_id`, `model_version`, `forecast_at`, `known_at`, `pd`, and an exact copy of `target`. `forecast_id` is unique. `known_at <= forecast_at` records that the prediction was frozen by its forecast date. Optional `weight` defaults to one; optional fields are `origin_grade`, Boolean `override`, `decision` (`approve`/`decline`), and `prediction_origin`. The latter must be `OUT_OF_TIME` for challenger assessment. Group slices are supplied separately rather than inferred.

Outcome records have unique `event_id`, matching `entity_id`, `event_at`, `known_at`, matching `default_definition`, and `event` equal to `default`, `exit`, or `rating`; rating events also require `grade`. Events not known by the evaluation cutoff are excluded. The horizon is `(forecast_at, forecast_at + horizon_days]`. A prior default or prior exit excludes a forecast. An exit before the horizon end censors an unobserved outcome, while an observed default on or before exit remains a default. Cure does not erase the first default inside a default-event horizon.

Coverage records require `entity_id`, `complete_through`, and `known_at >= complete_through`. The latest declaration known by the evaluation cutoff certifies complete event ascertainment through that date. A zero outcome requires both a matured horizon and complete coverage through its end. Missing or censored observations remain null. Early known defaults are retained as `target=1` but are not metric-eligible before maturity. Repeated entities/clusters are reported. A cluster must include all observations whose dependence is to be retained in inference.

Migration outcomes are derived from known, dated rating events, using the latest event by occurrence date, knowledge date, then event ID. A supplied future `outcome_grade` in a prediction is ignored. Without a later rating, the origin grade carries forward only for a mature, fully covered noncensored observation. For migration use, the coverage declaration must also certify complete rating-event capture. Mature defaults use the declared default grade. A bundle hash detects subsequent edits; it does not independently verify the bank's source declarations.

## Cohort metrics and uncertainty

`monitor_rating_cohort` requires grouping fields, a fixed `reference_window={start,end}` on forecast dates, positive integer `minimum_count`, and an uncertainty choice. Each group contains weighted AUC/Gini, Brier loss, exact log loss, mean PD, observed rate, observed-minus-predicted calibration error, migration counts, and override rate. Reference metrics use the same group and the specified forecast window. With time-specific groups, a different reference vintage can consequently have no observations; the function does not silently pool other groups. Empty outcomes and small observed samples have distinct statuses.

`uncertainty="none"` is descriptive. `iid_homogeneous_binomial` provides the two-sided Clopper–Pearson observed-rate interval and requires unit weights and distinct clusters. It explicitly assumes a common Bernoulli probability. At zero events the 95% upper bound is `1 - .025**(1/n)`, not zero. `independent_cluster_bootstrap` uses supplied resamples of cluster IDs. Every resample has the original number of distinct clusters, with replacement, and retains all rows of each selected cluster. Groups share the same draws. Percentile bands use linear/type-7 quantiles. AUC is unidentified in one-class resamples; identified replicate counts are reported. Degenerate bands are flagged and do not prove precision at sparse boundaries.

## Feature distribution changes

`detect_credit_feature_drift` requires `feature_order`, `method`, `permutations`, `multiple_testing`, and `dependence_assumption`. Nonnegative row weights travel with observations. Numeric methods drop missing feature observations (joint complete cases for MMD), report missing counts, and reject paths without positive observed support in both samples.

- `ks`: maximum absolute difference of weighted empirical CDFs, per feature.
- `wasserstein`: integral of their absolute CDF difference, per feature and in original feature units.
- `mmd_rbf`: joint weighted empirical squared kernel-mean distance with a positive, prespecified `bandwidth`. With normalized weights `a,b`, it is `a'Kxx a + b'Kyy b - 2a'Kxy b`; the RBF is `exp(-||x-y||²/(2 bandwidth²))`. It includes diagonals and is the biased empirical embedding statistic. It is not the unbiased U-statistic. The construction extends the empirical embedding in [Gretton et al., Section 2.2, equation (5)](https://www.jmlr.org/papers/volume13/gretton12a/gretton12a.pdf) to supplied weights; the weighted permutation design is an explicit implementation choice.
- `psi`: descriptive fixed-bin `sum((current-reference)*log(current/reference))`. `frozen_bins` gives each feature `kind="numeric"`, increasing `cutpoints` and two `support` endpoints, or `kind="categorical"` and unique string `levels`. Numeric bins are right-closed. Missing values have a separate bin; categorical unknowns have another. Positive `smoothing` is added to every weighted bin count before normalization. Current support violations/new categories are counted. PSI requires `permutations=None`/`NULL` and `multiple_testing="not_applicable"`; no significance threshold is attached.

For numeric methods, `permutations` is a B-by-pooled-N matrix of **zero-based** indices in both languages. Each row must be a complete permutation and B must be at least two. The first original-reference-size positions define the permuted reference sample. `exchangeable_rows` declares independent exchangeability; `exchangeable_clusters` additionally requires pooled `permutation_units`. Clusters must belong wholly to one original sample, and each permutation must move intact equal-size clusters in their original internal order. Unequal-size block movement requires a different design and is rejected.

The test uses `(1 + count(null >= observed))/(B+1)`, including a relative 1e-14 comparison tolerance, and reports the approximate Monte Carlo standard error `sqrt(p*(1-p)/(B+1))`. A 95% exact binomial interval for the underlying permutation-tail probability is also reported, so zero approximate standard error at a sampled boundary does not imply certainty. These inferential interpretations require independently sampled uniform valid permutations. Hand-selected paths may check arithmetic but do not establish valid p-values; exhaustive enumeration is not claimed by this API. Choose `none`, `holm`, or `bonferroni` explicitly for the returned family of tests. A feature shift does not establish a changed conditional default relationship.

## Sequential PD calibration drift

`detect_pd_calibration_drift` accepts strictly ordered records `{time, value, mature: true}` of zero-target residual aggregates. The caller derives mature observed-minus-expected rates, counts or standardized residuals under the declared `residual_scale`. It requires `method`, fixed `parameters`, shared `null_paths`, `null_spec`, and interior `alpha`. The null specification records `model_id`, `model_version`, `calibration_id`, `residual_scale`, `probability_measure="PHYSICAL"`, dependence (`independent` or `prespecified_dependent`), and `calibrated_before` no later than monitoring start.

CUSUM uses zero initialization, `up=max(0,up+r-allowance)` and `down=max(0,down-r-allowance)`, with statistic `max(up,down)` and nonnegative allowance. EWMA uses `z=(1-smoothing)*z+smoothing*r` with zero initialization and statistic `abs(z)`; `0<smoothing<=1`. These recurrences follow the [NIST CUSUM](https://www.itl.nist.gov/div898/handbook/pmc/section3/pmc323.htm) and [EWMA](https://www.itl.nist.gov/div898/handbook/pmc/section3/pmc324.htm) definitions, applied to centered residuals. Threshold calibration here is a separate simulation design, not the handbook's independent-normal three-sigma approximation.

Every row of the B-by-T null matrix must be an independent simulated **complete path** under the declared null; dependence within a path must reflect the monitored data. The horizon maximum is computed for each path. The threshold is ascending order statistic `ceil((B+1)*(1-alpha))`; insufficient B is rejected. Crossing is strictly greater than the threshold. Under exchangeability of the future null path and calibration paths, the order-statistic rank yields unconditional finite-horizon crossing probability at most alpha (ties are conservative). This statement is conditional on the null simulation model being appropriate; it is not a guarantee conditional on one fitted threshold or a certification of estimated model parameters.

Optional independent `validation_null_paths` requires `null_spec.validation_paths_independent=true`. It reports empirical crossing frequency and an exact binomial interval across independent whole paths. Calibration exceedance frequency is separately labeled. No independent false-alarm validation is implied when validation paths are absent. Extending the horizon or altering parameters requires recalibration.

## Paired challenger and fairness diagnostics

`compare_challenger_cohorts` requires the same target and evaluation cutoff. Unique `case_id` links pairs; entity, cluster, horizon, forecast date, weights and any jointly observed labels must agree. Only jointly eligible cases enter paired metrics; unmatched cases and eligibility disagreements are reported. Both predictions must declare out-of-time origin. The `selection_protocol` requires an ID, `evaluation_role="OUT_OF_TIME_TEST"`, and `multiple_challenger_policy` equal to `single_prespecified` or `separate_selection_and_final_test`. This declaration must correspond to the actual evaluation process.

Returned differences are challenger minus champion for AUC, Brier, exact log loss, calibration error and mean PD, with shared cluster-bootstrap bands. Impossible exact log-loss predictions retain infinite-loss status, and their differences are null rather than clipped. Decision flips are unweighted counts among known decision pairs. No single metric automatically promotes a challenger. Changes to selective outcome collection require substantive review, even when observed-case comparisons improve.

`diagnose_fairness_slices` requires supplied unique `{case_id,group}` labels, `reference_group`, documented `use_basis`, `minimum_count`, `risk_threshold`, and shared cluster resamples. Selection rate uses all known approve/decline decisions, including immature cases. TPR/FPR and prediction-error rate use only mature observed outcomes; positive prediction means `pd >= risk_threshold` and positive outcome means default. Calibration and Brier share that mature denominator. Group-minus-reference gaps use the same resamples. Null denominators, boundary samples, identified replicate counts and small-sample statuses remain explicit. Intervals are pointwise, not simultaneous fairness tests. The mathematical conflicts between group criteria described by [Kleinberg, Mullainathan and Raghavan](https://drops.dagstuhl.de/entities/document/10.4230/LIPIcs.ITCS.2017.43) motivate reporting several metrics; the methods do not infer group labels or certify legal/ethical fairness.
